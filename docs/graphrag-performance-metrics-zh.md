# GraphRAG 检索：性能指标报告

本报告覆盖两种固定数据集上的五种检索方法，将**质量**与**成本**放在一起汇报。
所有数字均来自 `tmp/graphrag/data/runs/` 下的 CSV，运行目录见第 7 节。
复现步骤见 `graphrag-external-reproduction-zh.md`。

## 1. 核心结论

自适应混合路由在排序质量上**并未胜过**固定混合；它大幅领先 graph-only，
仅仅是因为 graph-only 在这两个语料上是一个很弱的基线。如实汇总如下：

| 问题 | 回答 |
| --- | --- |
| 自适应是否优于 graph-only？ | 是，所有排序指标高出 36–150%，但 graph-only 是最弱的非退化基线 |
| 自适应是否优于固定混合？ | **否**。两个数据集上 MRR 与 NDCG 均低 5–13% |
| 自适应是否比 graph-only 便宜？ | 仅在 2Wiki 上成立（边扫描少 34%）。在 HotpotQA 上反而多花 65% |
| 是否有任何方法真正回答了问题？ | **没有**。F1 最高仅 0.0095，EM 全为 0 |

最后一行最为重要，第 5.3 节专门讨论。

### 4.3 如何如实解读这组对比

从上表可直接得出三条结论。

**相对 graph-only 的提升幅度很大，但基线很弱。**
graph-only 在 2Wiki 上召回 0.50、HotpotQA 上 0.38，远低于两个文本通道。
只引用“+66%”或“+150%”而不说明 graph-only 是最弱的非退化方法，会高估该结果。

**相对固定混合，自适应在排序上落后。**
MRR 在 2Wiki 上低 6.8%，在 HotpotQA 上低 13.0%。
自适应在 HotpotQA 的 Recall@10 上领先 0.7%，对于 500 条查询而言处于噪声范围内。
**当前的路由策略相对于更简单的固定融合，是在牺牲排序质量。**

**成本节省只在其中一个数据集上出现。**
自适应在 2Wiki 上比 graph-only 少扫 34% 的边，但在 HotpotQA 上多扫 65%；
且两个数据集上它携带的 token 都是 graph-only 的 2–3 倍，
因为它把文本通道的证据与图路径一并保留了下来。

## 5. 成本与答案层

### 5.1 实测 token 成本

`meanTokensRetained` 是真正进入答案层的证据的估算 token 数，
由 `chars4-v1` 计算（字符数除以 4，向上取整，下限为 1）。
这是**检索阶段**的数字，不是大模型的计费数字。

| 方法 | 2Wiki 均值 | 2Wiki 总计（500） | HotpotQA 均值 | HotpotQA 总计（500） |
| --- | --- | --- | --- | --- |
| BM25_ONLY | 2806 | 1,402,862 | 2854 | 1,427,150 |
| VECTOR_ONLY | 2603 | 1,301,437 | 2779 | 1,389,550 |
| GRAPH_ONLY | 842 | 420,933 | 658 | 329,090 |
| FIXED_HYBRID | 2676 | 1,338,250 | 2828 | 1,413,850 |
| ADAPTIVE_HYBRID | 2682 | 1,341,211 | 2837 | 1,418,700 |

`chars4-v1` 是近似估算。对英文文本而言，它相对 BPE 分词器通常偏低。
请把这些数字当作**方法之间的相对比较**，而非绝对 token 数。

### 5.2 若由大模型生成答案的 token 成本

检索层只返回证据片段，不调用任何模型。若某个部署接入了大模型，
单次查询成本可由保留 token 推出：

```
prompt_tokens  = 系统提示 + 问题 + meanTokensRetained
单次查询成本   = prompt_tokens × 输入单价 + 输出 token × 输出单价
```

以下为算例，取示意单价：输入 `$0.15 / 1M` tokens、输出 `$0.60 / 1M` tokens，
系统提示 200 tokens、问题 30 tokens、回答 50 tokens：

| 方法 | 输入 token | 每千次查询成本 |
| --- | --- | --- |
| GRAPH_ONLY | 1092 | $0.19 |
| FIXED_HYBRID | 2945 | $0.47 |
| ADAPTIVE_HYBRID | 2949 | $0.47 |
| BM25_ONLY | 3071 | $0.49 |

单价是刻意参数化的：请替换为实际所用模型的当前价格。
真正重要的是**相对关系**——graph-only 的输入成本约为其余方法的三分之一；
自适应与固定混合几乎相同，因为两者都保留了文本证据。

### 5.3 为什么所有方法的 F1 都接近零

五种方法的 F1 都落在 0.0022 至 0.0095 之间，EM 全为 0。
这反映的是**答案层**的性质，而非检索失败：

- 答案消费者是**抽取式**的：它从检索到的 chunk 中返回一个片段。
- 标准答案是短实体（`Małgorzata Braunek`、`yes`、`2`）。
- 检索到的 chunk 是实体名列表或多句段落，因此抽取器极少恰好输出标准答案字符串。

唯一的例外很有信息量：**召回最低**的 GRAPH_ONLY 反而 F1 **最高**
（2Wiki 0.0095，HotpotQA 0.0079）。
它窄而实体密集的证据，使片段抽取更容易命中短答案。
因此在本设置下 Recall 与 F1 度量的并不是同一件事，
**不应使用 F1 来给这些方法排序**。
有意义的 F1 需要生成式答案模型，而本模块并不包含。

自适应相对固定混合仅增加约 1–2%。延迟数字与机器相关，应在目标主机上重新测量。
