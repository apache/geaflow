# GraphRAG 设计缺口修复与完整实现（TDD 迭代）

## 1. 目标与假设

### 目标

关闭 `tmp/graphrag/geaflow-adaptive-hybrid-retrieval-issue-zh.md` 审计中全部缺口（P0 7 项 + P1 4 项 + P2 7 项），使 `tmp/graphrag/geaflow-adaptive-hybrid-retrieval-issue.md` 的完整设计达到「代码 + 测试 + 端到端产物」三重验收，并支持后续迭代复核。

### 假设

1. 当前分支 `codex/graphrag-f05-cost-accounting`（HEAD `40dbf6882`）有 92 项未提交改动，**以工作区现状为基线**，修复直接叠加，不做 rebase。
2. 「完整实现」以**代码契约 + 自动化测试**为主判据；需要外部数据/压测/许可证的项（评测产物重跑、load SLO、license 审阅）在本环境不可完整执行时，产出**可执行脚本 + 会话内可验证的 smoke 证据**，并在文档中明确「未在本环境执行」的边界，不伪造产物。
3. 所有 Java 变更遵循 `tools/checkstyle.xml`（4 空格、200 列、Apache header、无未用 import）；Python 变更遵循现有 runner 风格。

### TDD 工作流（每个缺口一个循环）

```
1. RED    写失败测试（精确断言设计要求，而非"类存在"）
2. GREEN  最小实现使测试通过
3. REFACTOR 消除重复、补 Javadoc
4. VERIFY mvn -o -pl geaflow-ai test -Djacoco.skip=true  /  pytest tools/graphrag/tests -q
5. COMMIT 一个缺口一个 commit（feat/fix + scope）
```

**关键纪律**：测试必须覆盖**生产装配路径**（`RecallService` 真实构造链），而非仅显式传参的单元测试——这正是本次审计发现「测试全绿但设计空转」的根因。

### 阶段 C：图视图惰性化（P1-1 / F-03）

#### C1. VersionedGraphView 复用 int[] 索引【TDD】

1. **RED**：`VersionedGraphViewLazinessTest`
   - 构造 100k 度顶点的 snapshot（单顶点 100k 边）→ 断言 `neighbors(entityId)` 返回的 `List` 是**惰性视图**（调用 `size()` 不触发 O(E) 复制；遍历时按需读，用 `AbstractList` 计数器验证未复制全表）。
   - 断言 `prioritizedNeighbors(...,cap)` 在排序前截断（有界扫描），cap 之后的边不全部被排序。
   - 断言 overlay（parent+delta）路径同样惰性。
2. **GREEN**：
   - `VersionedGraphView` 内部改为复用 `IndexedGraphNeighborProvider` 的 `int[]`+`edges` 表示：
     构造不再 `buildNeighbors` 全量 `List`，改为存 `edgeIndexesByEntity: Map<String,int[]>` + 不可变 `List<GraphEdgeRef> edges`。
     `neighbors()` 返回 `AbstractList` 视图（照抄 `IndexedGraphNeighborProvider:125-147` 模式）。
   - overlay 路径：只对**被 delta 触及的顶点**重算 `int[]`（`overlayEdgeIndexes`），其余继承 parent；tombstone 用 `removedEdgeKeys` 过滤。
   - `prioritizedNeighbors(entityId, priority, limit)` 改为 `NeighborBatch.select(neighbors(entityId), priority, limit, neighbors.size())`（复用现有有界实现）。
3. **REFACTOR**：抽出 `GraphNeighborIndex` 值对象（`int[]` + edges），供 `IndexedGraphNeighborProvider` 与 `VersionedGraphView` 共用，消除重复。
4. **VERIFY**：`VersionedGraphViewTest`（11 项）必须全绿（语义等价）+ 新增惰性测试；`ArtifactBundleLoaderTest` 全绿。

## 5. 风险、限制与否决方案

### 风险

1. **`VersionedGraphView` 惰性化改动面大**（359 行，11 项测试 + bundle 加载路径）。缓解：保持 `neighbors()` 返回类型不变（`List`），仅换内部表示；用「等价性测试」保证 delta+tombstone 合并结果与全量重建逐字段相等（已有 `VersionedGraphViewTest:42` 可复用）。
2. **`queryId` 语义变更**可能影响现有 JSON 断言。缓解：先跑 `RetrievalProvenanceContractTest`/`RetrievalApiJsonTest` 定位，必要时把「requestId 进 trace」与「queryId 确定性」分离。
3. **新增配置项**可能与现有 `application.yml` 冲突。缓解：全部带默认值 + `@Inject` 缺省，`validateConfiguration` 仅在显式非法时报错。
4. **`/ready` 变更**可能让部分现有测试从 200 变 503。缓解：仅当 fixture 三类全备时才 200；legacy keyword-only fixture 保留原有 `keywordReadiness` 分支（灰度兼容）。

### 明确不在本次范围（设计已排除）

ANN/在线 embedding、跨编码器 reranker、学习型/Bandit 路由、MCP、可视化、Planner/图计算运行时改造。

### 否决方案

- ~~把 5 个图参数做成硬编码常量~~：违背「可配置、可复现」，且 benchmark ablation 需要不同取值。
- ~~`edgeScanBudget` 继续等于 `candidateBudget`，仅在报告层区分~~：设计明确要求独立次级成本口径与可量化对比。
- ~~为答案层只写文档不给端点~~：F-10 要求「上层可直接运行」的交付形态。

### 非阻塞开放问题

- 全量 HotpotQA/2Wiki 重跑与 600s soak 需生产环境；本次交付脚本 + smoke 证据，全量结果标注待执行。
