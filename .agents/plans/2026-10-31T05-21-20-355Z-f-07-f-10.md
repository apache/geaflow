### 缺口 F07-G1：`/ready` 用字符串拼接 JSON（低危、真实）

`GeaFlowMemoryServer.ready()` 手工拼接：
```java
return "{\"status\":\"" + ... + "\",\"graphName\":\"" + String.valueOf(status.getGraphName())
    + "\",\"graphVersion\":\"" + String.valueOf(status.getGraphVersion())
    + "\",\"reason\":\"" + status.getReason() + "\"}";
```
`graphName`/`graphVersion` 来自 `RetrievalProperties`（可经环境变量注入），
若含 `"` 或反斜杠会产**非法 JSON**；`null` 会输出字面量 `null` 而非 JSON null。
`/metrics/retrieval` 同样手工拼接，但其内部值均经 `RetrievalApiJson.toJson` 序列化，风险只在数值字段（安全）。

**修复**：改用已有的 `RetrievalApiJson.toJson` 输出一个不可变小对象，或对字符串做 JSON 转义。

### 缺口 F07-G2：HTTP 层缺 5 mode × 3 execution 的完整契约测试

`MemoryServerTest` 仅 2 个测试。五种 mode 在 HTTP 层只测了「带 queryVector 时 BM25_ONLY/GRAPH_ONLY 返回 400、VECTOR_ONLY/HYBRID 返回 503」，
**未验证 KEYWORD**；三种 execution mode 的覆盖在项目内 Java 服务层
（`GraphRagMvpEndToEndTest`），**不在 HTTP 层**。F-07 验收原文是「HTTP contract 覆盖五种 mode、三种 execution mode」。

**修复**：在 `MemoryServerTest` 补一个契约测试，对 5 种 mode 与 3 种 execution 逐一发 HTTP 请求，
断言状态码、`X-Request-Id` 回显、trace 中的 `mode`/`executionMode`。

## 4. F-08：主体已实现，缺 ablation

### 已实现（有证据）

| 条目 | 落点 |
|---|---|
| HotpotQA distractor adapter | `source_loader._hotpot_parquet_record`（`dataset != "hotpotqa"` 时显式拒绝） |
| 2WikiMultiHopQA adapter | `source_loader._canonical_record` 支持 `paragraphs`/`context`/`passages`，`supporting_facts` 列表；`manifests/2wikimultihopqa-dev-v2.json` |
| 原始数据只从 manifest/cache 读取 | `_resolve_source` + `_verify_checksum` + 大小/zip 条目上限 |
| Evidence Recall@K / MRR / NDCG / EM / F1 / percentile | `eval/metrics.py`（`evidence_recall_at_k`/`reciprocal_rank`/…）、`eval/retrieval.py`（`_ndcg_at_k`）、Java `RankingMetrics`/`AnswerMetrics`/`Percentile` |
| relation path hit rate | `RankingMetrics.relationPathHit`、`retrieval.py` |
| P50/P95 latency、candidate count、edge scans、token cost | `benchmark_http.py` 行字段 + 汇总 CSV |
| 六方法比较 | `benchmark_http.py` 的 `METHODS = ('BM25_ONLY','VECTOR_ONLY','VECTOR_OVERFETCH','GRAPH_ONLY','FIXED_HYBRID','ADAPTIVE_HYBRID')`，`run()` 遍历 `METHODS` 产出逐方法与汇总 CSV |
| JSONL/CSV 原始结果 + 汇总报告 | `run()` 输出 rows CSV + summary CSV |
| 失败样本不静默丢弃 | `request()` 异常路径返回 `(0, {}, elapsed, str(error))`，注释明确「record failures as data so runs are never silently partial」 |
| 确定性 | 稳定 `requestId`（query 身份的 sha256 前 32 位）、`--exact-ranking` |

### 缺口 F08-G1：ablation 完全缺失

文档要求「支持多级 hard budget 和 **no-anchor / high-degree / lexical / semantic / multi-hop** ablation」。
全仓 grep `ablation` = 0 命中。

**修复**：在 `benchmark_http.py` 增加 `--ablation` 选项，对上述 5 类条件各产出一组变体行
（以 `method` 后缀或新增 `ablation` 列区分），并在汇总中单列。纯 Python 侧改动，不动 Java 检索语义。

## 5. F-09：基本已实现，缺 citation 覆盖率

### 已实现（有证据）

| 条目 | 落点 |
|---|---|
| `AnswerRequest`/`AnswerResponse`/`Citation`/`abstentionReason` | `answer/` 包，`abstentionReason` 9 处引用 |
| 引用只指向返回的 Evidence ID/source/chunk/path | `Citation(evidenceId, sourceId, chunkId, pathId)` 四参构造 |
| 确定性 context assembler：按 fused/rerank score 选证据、去重 source/chunk、用 F-05 TokenEstimator 截断、保留引用映射 | `ExtractiveAnswerConsumer.consume`（score 降序 + evidenceId tie-break；`sources` 集合去重；`estimator.estimate` 截断；逐 chunk 记 Citation） |
| extractive answer 接口 + 可替换 synthesizer SPI | `ExtractiveAnswerConsumer`、`AnswerSynthesizer` SPI、`DefaultAnswerSynthesizer` |
| 空证据 / provenance 无效 / token 不足 / 无法支撑 → 结构化 abstain | `NO_EVIDENCE`、`TOKEN_BUDGET_OR_INVALID_PROVENANCE`、`EMPTY_SUPPORTED_ANSWER` |
| answer trace 与 retrieval trace 关联 | `AnswerResponse.getTraceIds()`（收集 `GraphEvidenceTrace.getQueryId()`）；`getEvidenceIds()` |
| 检索只返回 Evidence 的旧 API 不变 | answer 层是独立包，`RetrievalService` 未引用 |

### 缺口 F09-G1：缺「citation 覆盖率」

文档要求 trace「记录 evidence IDs、使用的 tokens、**引用覆盖率**和 synth/suppress reason」。
`AnswerResponse` 有 `evidenceIds`/`tokens`/`abstentionReason`，但 grep `coverage` 在 `answer/` = 0 命中。

**修复**：在 `AnswerResponse` 增加 `getCitationCoverage()`（= 被引用 Evidence 数 / 输入 Evidence 数，
输入为 0 时返回 0.0），并加测试固定边界。

## 7. 实施步骤（按价值/风险排序）

### 步骤 1 — F07-G2：补 HTTP 契约测试（最高价值，纯测试）
新增 `MemoryServerTest` 用例，覆盖 5 mode × 3 execution 的 HTTP 契约，
断言状态码、`X-Request-Id`、trace `mode`/`executionMode`。这是四份文档中**唯一完全缺失的验收项类型**
（契约测试），且是 F-10「clean checkout 可复现」的前提。

### 步骤 2 — F07-G1：`/ready` 改结构化 JSON 输出
用 `RetrievalApiJson.toJson` 替代字符串拼接，消除 `graphName` 含引号时的非法 JSON 风险，
并补一个含特殊字符的 graphName 用例。

### 步骤 3 — F09-G1：`AnswerResponse.getCitationCoverage()`
小改动 + 边界测试（输入为空、全部被引用、部分被 token 预算截断）。

### 步骤 4 — F08-G1：`benchmark_http.py` 增加 `--ablation`
纯 Python，输出加 `ablation` 列，覆盖 no-anchor / high-degree / lexical / semantic / multi-hop，
并确保默认（不带 `--ablation`）行为与输出格式不变。配套 `tests/test_http_benchmark.py` 用例。

### 步骤 5 — F10-G1..G4：补 `graphrag-operations.md`
补全 5 种 mode、8 个错误码、配置默认值/硬上限表、4 类 curl 样例、数据集许可/缓存要求/故障排查/版本矩阵。
纯文档，无代码风险。

## 9. 风险

- R1：`/ready` 改结构化输出会改变字段顺序（`LinkedHashMap` 可控），但不改变字段名与语义；`MemoryServerTest.legacyWorkflow` 断言 `contains("GRAPH_NOT_LOADED")`，需确认仍成立。
- R2：`--ablation` 新增列会改变 CSV 表头；旧结果文件的列不匹配。缓解：新增列默认空，读取侧兼容缺失列。
- R3：`getCitationCoverage()` 新增字段会改变 `AnswerResponse` 的 JSON 形状；无 codec 落盘依赖，但需检查是否有 golden 断言。
- R4：补 HTTP 契约测试需真实启动 Solon（`@SolonTest`），可能引入端口占用/时序 flaky；沿用现有 `MemoryServerTest` 模式与端口配置。
