#### 缺口 F04-G1：最低关联分数只过滤单条边，不终止扩展（语义偏离）

设计文档原文：「当增长率超过扩散阈值、边际产出低于下限或**剩余路径低于最低关联分数时，提前终止扩展**」。
F-04 分册亦列为停止条件之一。

实现（`GraphRetriever` 约 315 行）：
```java
double score = associationScore(state, edge, targetId, provider, config);
if (score < config.getMinAssociationScore()) {
    continue;   // 跳过这一条边，继续扫描其余边
}
```
即：低分边被逐条 `continue` 丢弃，**不会**触发 hop 或整个图阶段的终止，也不产生对应 stop reason。
`RecallStopReason` 中无关联分数停止原因。

后果：当一个 hop 的绝大部分边关联度都低于阈值时，仍会穷尽 `edgeScanBudget` 扫描，
违背设计文档「提前终止扩展」的成本控制意图，且 trace 无法表达「因分数过低而停止」。

**修复（见 §5 步骤 2）**：增加「本 hop 存活边比例低于阈值即终止该 hop」的判定，
新增 `RecallStopReason.LOW_ASSOCIATION_SCORE`，并在 `GraphStats` 记录被过滤边数与被终止的 hop。
