# GraphRAG 自适应路由模块分析：消融实验、失效归因与开放问题

对应维护者评审的第 3 点：补充完整的组件级消融，解释自适应决策为何未稳定优于单路方案，
并把当前决策模块的局限性作为开放问题留给后续研究者。

本文所有数字来自 `tmp/graphrag/data/runs/` 下的运行产物，可用
`tools/graphrag/ablate_adaptive.sh` 与 `tools/graphrag/sweep_fusion.sh` 复现。
代码版本为 PR 分支 `codex/graphrag-adaptive-hybrid-retrieval`
（修复提交 `dbaa0929a`，复现管线加固 `fee160853`）。

## 1. 结论摘要

| 问题 | 回答（500 条主报告口径，详见 `performance-metrics.md`） |
| --- | --- |
| 自适应是否优于 graph-only 单路？ | 是，幅度很大（2Wiki MRR +49.6%，HotpotQA +146.5%），但 graph-only 是最弱的非退化基线 |
| 自适应是否优于文本单路？ | **分数据集**：2Wiki 上优于 BM25（+6.8%）与 VECTOR（+10.0%）；HotpotQA 上优于 VECTOR（+5.3%）但**仍落后 BM25 2.3%** |
| 自适应是否优于固定混合？ | 旧默认下落后 6.8% / 13.0%；**重新标定后两个数据集都领先：2Wiki +2.1%、HotpotQA +0.7%** |
| 自适应的召回是否也领先？ | 2Wiki 上是（0.8495 最高）；HotpotQA 上否（0.9270，落后 BM25 的 0.9673 与固定混合的 0.9460） |
| 自适应的七个决策组件都有用吗？ | 否。权重比值是唯一测出大效应的组件；三条规则经三轮验证无效果，根因已定位 |

**因此“自适应未稳定优于单路方案”仍然部分成立**：在文本通道极强的 HotpotQA 上，
BM25 单路的 MRR 与召回仍然更高。修复消除的是**配置造成的无谓落后**，
而不是证明自适应在所有语料上都占优。

最重要的一条：**自适应未稳定优于单路方案的原因不是"自适应思想无效"，
而是出厂配置把一个更弱的通道（图）的排序贡献设成了更强通道（文本）的 8 倍。**
把该比值改为 1:4 后，自适应在 2Wiki 上转为领先固定混合。

| 设置 | 取值 |
| --- | --- |

用以证明覆盖只作用于自适应路径。

## 3. 完整组件消融

### 3.1 第二轮：权重已重新标定、多跳仍开启（`max-hop=2`）

2WikiMultiHopQA，200 条。FIXED 对照 MRR 0.7545、Recall 0.8454、NDCG 0.7295、边扫描 36.15，
在全部条件下完全相同。

| 条件 | 覆盖 | 中和的组件 | MRR | 相对基线 | 边扫描 |
| --- | --- | --- | --- | --- | --- |
| baseline | 无 | — | 0.7738 | — | 31.135 |
| no-router | `graph-weight=1.0`、`text-weight=1.0` | 融合中的图偏好（变为 1:1） | 0.7711 | -0.35% | 31.135 |
| no-graph-fusion | `graph-weight=0.0` | 图证据的排名贡献 | 0.7708 | -0.39% | 31.135 |
| no-probe-share | `probe-share=0.5` | 文本探测的预算预留 | 0.7705 | -0.4% | 31.5 |
| no-cascade-gate | `min-probe-evidence=1`、`min-probe-score-gap=0` | 级联阶段门控（只能放宽，校验器拒绝 0） | 0.7682 | -0.7% | **38.055（+22%）** |
| no-replan | `max-replan-count=0` | 请求中途的计划修订 | 0.7738 | 0 | 31.135 |
| no-idf-trigger | `high-average-idf=1000` | 词法置信度规则 | 0.7738 | 0 | 31.135 |
| no-degree-trigger | `high-candidate-degree=1000000` | 高点度收敛规则 | 0.7738 | 0 | 31.135 |
| growth-4 | `high-growth-rate=4.0` | 扩散上限放宽 | 0.7713 | -0.32% | 30.94 |
| growth-8 | `high-growth-rate=8.0` | 扩散上限进一步放宽 | 0.7679 | -0.76% | 30.94 |

可读出的结论：

- **级联门控有净收益**：放宽它多扫 22% 的边，MRR 反而下降 0.7%，召回仅 +0.75%。
- **探测份额 0.4 略优于 0.5**，但差异在噪声边缘。
- **图证据的排名贡献有少量正面价值**：完全置零（no-graph-fusion）比 1:4 低 0.39%。
- 三个条件与基线**逐位相同**，需要归因，见第 4 节。

### 3.2 第三轮：结构修复后的复核（`max-hop=1`）

| 条件 | MRR | Recall@10 | NDCG@10 | 边扫描 | replan 计数 |
| --- | --- | --- | --- | --- | --- |
| baseline | 0.7738 | 0.8504 | 0.7410 | 31.135 | 0.80 |
| no-replan | 0.7738 | 0.8504 | 0.7410 | 31.135 | 0.00 |
| no-idf-trigger | 0.7738 | 0.8504 | 0.7410 | 31.135 | 0.80 |
| no-degree-trigger | 0.7738 | 0.8504 | 0.7410 | 31.135 | 0.80 |

基线与第二轮完全一致，而 replan 计数从 1.28 降到 0.80：
**hop 边界的空转事件被移除，检索结果不变。**

## 4. 三个零差异条件的归因

这些实验本身有效——覆盖确实生效（`no-replan` 把 replan 计数降到 0），
对照组保持稳定。无效的是被测组件，而且原因各不相同。

### 4.1 词法规则：被分支优先级遮蔽，与阈值无关

```java
if (anchored)               { GRAPH_DOMINANT_FUSION }   // 199/200 条查询（99.5%）
else if (averageIdf >= ...) { LEXICAL_CONFIDENCE }      // 1 条
else if (queryLength >= 12) { SEMANTIC_QUERY }          // 0 条
```

锚点分支优先，词法/语义分支在结构上不可达，**改阈值不可能产生影响**。

需要更正一个流传过的错误归因："阈值 1.5 面对实测中位数 3.01 所以无法触发"是**反**的——
判定为 `averageIdf >= threshold`，若分支可达它应当**总是**触发（实测 200/200 满足 `idf>=1.5`）。
旧阈值的问题其实是**低于实测最小值 1.56，毫无区分度**，现已重标定为 4.0（分布 p90）。

### 4.2 高点度规则：触发了，但作用在从不饱和的上限上

`candidate_degree > 32` 的查询有 **46/200（23%）**，规则并非不可达。
但逐条对比这 46 条在有无规则下的行为：

| 观测 | 结果 |
| --- | --- |
| 邻居采样数中位数 | 1.0 |
| 移除规则后邻居数变化的查询 | **0 / 46** |
| 移除规则后边扫描变化的查询 | **0 / 46** |
| 移除规则后证据列表变化的查询 | **0 / 46** |

邻居上限从 16 减半到 8 约束不到任何实际扩展；扩张又被扩散停止抢先终止。

### 4.3 重规划：两层重复停止 + 没有可分配的稀缺资源

两层原因叠加：

1. **跨层重复**。96 条到达 hop 边界的查询，其图通道停止原因 **96/96 全是
   `DIFFUSION_GROWTH_LIMIT`**——图检索器已自行停止，策略层的停图只是重复确认。
   为排除"阈值太紧"，把扩散上限放宽到 4 和 8：边扫描不增（31.1→30.9）、
   图证据产出反而下降（2.73→2.37），说明**第二跳没有可扩展材料**。
2. **预算不饱和**。`max-hop=1` 使 hop 边界消失后，`no-replan` 依然与基线逐位相同，
   说明连文本探测边界的预算重分配也无效：文本通道在 `exactRanking` 下全量扫描，
   图通道配额 60 与 98 都远超其约 2.7 条的实际产出。
   **主约束为 `CANDIDATES` 且配额远超产出时，重规划没有稀缺资源可分配。**

### 4.4 一个被代码修复过、但仍不改变结果的真实缺陷

重规划曾经连"决策正确性"都是错的：额度耗尽时策略回退到执行前特征快照
（`graphGrowthRate=0`），导致 hop 边界永远看不到刚测到的扩散增长。
修复后，验证切片上 17 次"预算回滚"全部变为真实停图。
**这类缺陷不改变指标，但会让 trace 撒谎**，因此值得单独修复与回归测试。

## 5. 自适应为何未稳定优于单路方案

按实测影响从大到小，四个原因：

### 5.1 融合权重的先验与数据相反（主因，已修复）

旧默认 `graph-weight=2.0`、`text-weight=0.25`，图的倒数排名贡献是文本的 **8 倍**。
而两个语料上文本通道都更强：

| 数据集 | BM25 MRR | GRAPH_ONLY MRR | 文本领先 |
| --- | --- | --- | --- |
| 2WikiMultiHopQA | 0.7368 | 0.5260 | 0.2108 |
| HotpotQA | 0.8254 | 0.3272 | 0.4982 |

给更弱的通道加权，代价就是排序质量。权重扫描（每比值重启服务、200 条、固定文本权重 1.0）：

| 图:文本 | 2Wiki MRR | 相对 FIXED | HotpotQA MRR | 相对 FIXED |
| --- | --- | --- | --- | --- |
| 0:1 | 0.7708 | +2.2% | 未测 | — |
| **1:4（新默认）** | **0.7738** | **+2.6%** | **0.7901** | **-0.1%** |
| 1:2 | 0.7729 | +2.4% | 0.7851 | -0.7% |
| 1:1 | 0.7711 | +2.2% | 0.7745 | -2.1% |
| 2:1 | 0.7222 | -4.3% | 未测 | — |
| 4:1 | 0.7033 | -6.8% | 未测 | — |
| 8:1（旧默认） | 0.6958 | -7.8% | 0.6720 | -15.0% |

**旧默认值是两个数据集上所测范围内的最差点。** 注意 0:1 略低于 1:4，
说明图通道的排名贡献仍有少量价值；被推翻的是"图应占主导"，不是图通道本身。

该错误先验的来源也已被定位并修复：早期运行对一份**已不存在语料的 chunk id** 打分，
得出"文本召回 0.002、图通道领先"的假象。评测管线现在会在证据 id 命名空间不匹配时直接中止。

### 5.2 决策是静态规则表，从未对数据拟合

`DeterministicRulePolicy` 把"特征—阈值"对映射到计划。它可复现、可审计，但七个阈值
最初全是手工默认值，没有任何一个经过扫描。扫描后只有融合权重与 IDF 阈值被改动，
其余阈值在实测中不承重。

### 5.3 三条规则没有可作用的对象

见第 4 节。它们出现在策略里、写入每条 trace，却不贡献排序质量。

### 5.4 解耦词法/语义规则实测无收益（第三轮）

给词法/语义规则真正的决策域（与锚点解耦）后：

| 数据集 | MRR 变化 | Recall@10 变化 |
| --- | --- | --- |
| 2Wiki | -1.43% | -3.09% |
| HotpotQA | -0.16% | -3.65% |

偏重单一文本通道会损失另一通道的互补证据，等权更好。
**结论：这两个特征不是有效的通道侧重信号，建议删除或永久关闭该分支，不要再调阈值。**

## 6. 当前决策模块的局限性（开放问题）

按可研究性排序，每条都附带已有的实测约束，避免后来者重复无效尝试。

### 6.1 全局常量权重已到天花板

1:4 在 2Wiki 上领先固定混合 2.6%，在 HotpotQA 上仅追平（-0.1%）。
**单一全局值的上限大致就在这里。** 下一步是按查询加权，例如用锚点置信度、
文本探测分数差或第一跳产出率来缩放图权重。

### 6.2 缺乏"图何时有帮助"的预测特征

当前七个特征（IDF、查询长度、锚点数、锚点置信度、点度、扩散率、探测分数差）中，
只有锚点与扩散率被证明承载决策。需要回答：哪些特征能预测图证据对**该条**查询有增益？
候选信号包括锚点覆盖率、第一跳的新证据率、图文本证据重叠度。

### 6.3 多跳能力在本语料上无验证对象

放宽扩散上限不能产生更多工作，说明图扩展在第一跳后缺少材料。
**在多跳结构真实的语料上重新评估**之前，不应据此删除多跳实现；
`max-hop` 已可配置（默认 1，设为 2 即恢复）。

### 6.4 重规划需要稀缺资源场景才有意义

当前的 `CANDIDATES` 主约束下预算从不紧张。后续实验应改用 `TOKENS` 或 `LATENCY`
为主约束、或显著缩小 `candidateLimit`，才能判断重规划是否值得保留。

### 6.5 策略不可学习，且缺少在线反馈

规则表无法从"哪条证据最终被引用"中学习。引入拟合型策略时必须同时保住
设计所要求的可复现审计链（`policyId`/`policyVersion`/参数快照/replan 事件），
这是一个尚未解决的工程约束。

### 6.6 答案层与检索层仍未打通

所有方法 F1 约 0.002–0.010、EM 为 0。这是抽取式答案消费者与短实体标准答案的结构性错配，
不是检索失败。**召回最低的 graph-only 反而 F1 最高**，说明 Recall 与 F1 度量的不是同一件事。
任何端到端答案质量声称都需要生成式答案模型与一次全新评测。

### 6.7 结论的外推性有限

所有数字来自两个英文多跳基准的确定性前缀切片，未做参数搜索之外的语料验证，
未做并发压力测试。组件消融在 HotpotQA 上仍未完整重跑（该处只做了权重扫描与 max-hop 对照）。
